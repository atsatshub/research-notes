仕事でのAIの使い方の例：メール・要約・議事録・Excelなど場面別の指示文、書き方の型、使う前の決まりと確かめ方（2026年版）

  • 調査日: 2026年11月20日
  • 仕事・学習の道具

要点まとめ

  • 白書の調査では、答えた企業の86.4%が何らかの業務で生成AIを利用[1]
  • 使い道で一番多いのは「議事録・メール作成補助」で、約7割[1]
  • 指示文は「役割・目的と背景・材料・出力の形」を書き、やり取りで直す[2][3]
  • 許可のないAIに、個人情報・取引先の秘密・社外秘を入れない[2][4]
  • 出力は下書き。事実・数字・出典は、元の資料で確かめてから使う[2]

生成AI（文章や画像を作るAI）は、メールの下書きや会議メモの整理など、職場の身近な仕事で使われるようになりました。この記事では、東京都が職員向けにまとめた「文章生成AI活用事例集」と「生成AI利用の手引き」[5][2]、総務省・経済産業省の「AI事業者ガイドライン」[6]、個人情報保護委員会の注意喚起[7]などをもとに、職場ですぐ試せる使い方を、場面ごとの指示文（プロンプト）の例と一緒にまとめました。AIサービスの紹介や比較ではなく、どのサービスにも共通する書き方、使う前の決まり、出力の確かめ方を中心にしています。

仕事でAIはどこまで使われているか

日本の前年度（2024年度調査）は26.7%でした[8]。ただし2025年度の調査から15〜19歳を対象に加えたため、同じ条件での比較ではありません。20歳以上に限ると52.2%です[8]。調査は2026年1〜2月のインターネット調査で、日本は10歳代（15歳以上）から60歳代の1,236人が答えました[10]。

企業：前年度の調査から大きく増えた

答えた企業の86.4%が、何らかの業務で利用[1]

令和8年版情報通信白書の企業調査では、自社の何らかの業務で生成AIを使っていると答えた割合は、日本で86.4%でした。前年度の調査から大幅に上がり、米国・ドイツ・中国との差も縮まったとしています[1]。この調査に答えたのは、従業員10名以上で2025年までにデジタル化に取り組み始めた企業の管理職以上で、日本は515社です[10]。生成AIの活用方針に「わからない」と答えた企業は除いて集計しています[1]。日本の企業全体の割合ではない点に注意してください。

使い道で一番多いのは「議事録・メール作成補助」

日本の回答企業では、約7割がこの用途で活用[1]

業務の種類ごとに見ると、日本では「議事録・メール作成補助」での活用が約7割と最も高く、「営業・販売」が約6割、「社内ヘルプデスク」が約5割と続きます[1]。導入の効果を実感していると答えた割合も「議事録・メール作成補助」が約7割で、ほかの用途より目立って高い結果でした[1]。

政府職員の実証では、使う人と使わない人の差も

満足は71.7%、一方で31.2%はほとんど使わず[11]

デジタル庁は、政府職員向けの生成AIの環境「ガバメントAI 源内」の大規模な実証を、政府職員18万人を対象に行っています。利用状況のアンケート（6,439人が回答）では、71.7%が「満足」と答え、業務時間の短縮効果は1人あたり週平均約1.83時間（約110分）と推計されました[11]。一方で、回答者の31.2%はほとんど、または全く使っていませんでした[11]。これは政府職員の実証の結果で、民間の職場にそのまま当てはまるとは限りません。

くわしく
  • デジタル庁の職員の試行（2025年5〜7月）では、約1,200人中約950人が利用した[12]
  • 同じ試行で、課長級の職員の半数は利用実績がゼロだった[12]

向いているのは「たたき台」づくり

下書き・要約・言い換えに使い、正しさは人が確かめる

東京都の事例集は、企画・アイデア出し、文案作成、要約、メール作成、会議の開催、広報発信、ローコード等の生成（Excel の関数づくりなど）、翻訳の場面ごとに使い方を紹介しています[5]。一方で東京都の手引きは、生成AIの回答は表現が自然なので正しいと感じてしまうが、最新の情報を反映していなかったり、偏った価値観が入ったりして、必ずしも正確とは限らないとしています[2]。

くわしく
  • 文部科学省の指針も、お便り・通知文・案内文のたたき台づくりを校務の例に挙げている[13]
  • もっともらしい誤り（ハルシネーション）は、軽減策があっても完全には解消できない[14]
  • AIの出力を人の評価の参考にするなら、評価される人にAIを使うことを知らせる[6]

場面別の使い方と指示文の例

東京都の「文章生成AI活用事例集」（2024年1月）は、都の職員が実際に使った指示文と回答の例を、場面ごとに載せています[5]。下の表は、この事例集と東京都の手引きをもとに、職場でよくある場面を整理したものです。

場面別の使い方と指示文の例。「」内は東京都の事例集・手引きから要点だけを引用。注意の列のうち出典のないものは筆者の提案
場面使い方指示文の例（要点）注意
メール話し言葉で書いた要点を、ビジネスメールの文にする「日本語のビジネスメールのベストプラクティスに従い」清書を作らせる[5]相手・日付・約束した内容は自分で確かめる
要約長い文を、やさしい言葉の箇条書きにする「カタカナ語は優しい日本語に変換し」箇条書きに → 「さらに半分程度に短くしてください」[5]元の文と見比べ、抜けや言い過ぎがないか確かめる
議事録・報告会議中の箇条書きのメモから、報告用の文書を作る「以下の会議メモから報告用資料の作成を」[5]「事実と相違がないかどうかを確認してから使用しましょう」[5]
校正誤字脱字と言い回しを直し、直した箇所も一覧にする「あなたは、プロの編集者です」＋直した箇所を箇条書きで[5]一覧を見て、意味が変わった直しがないか確かめる
Excel表の列の中身を伝えて、関数（式）を作らせる列ごとに何が入っているかを書き、「E列に関数を入れたいです」[5]答えが分かっている数行で、式を試してから使う
アイデア出し立場と課題を書いて案を出させ、次にリスクを挙げさせる「項目ごとに期待される効果を説明してください」→ 次にリスクを聞く[5]案はそのまま採用せず、人が選ぶ
翻訳まず日本語で文案を作って確かめ、次に英語にする「日本語の招待状案を英文にして下さい」[5]英文をうのみにせず、内容を確かめてから送る[5]
公開前のチェックSNSなどに出す文の、炎上のリスクを聞く「どの程度炎上のリスクがあるか、教えてください」→ 修正案と修正点を出させる[5]出すかどうかの最後の判断は人がする
資料にもとづく質問渡した資料の中だけで答えさせる「この資料に記載が無い場合はその旨回答してください。」[2]答えの根拠の箇所を、資料で確かめる

メール：要点のメモから下書きを作る

伝えたいことを短く並べ、清書を頼む

東京都の事例集では、お礼と結果の連絡を、くだけた話し言葉で短く書いて入れ、ビジネスメールの清書を作らせています。必要な要素を簡単に入れるだけで、話し言葉からビジネスの文章を作れると説明しています[5]。相手に伝えづらい話ほど、AIに文案を考えてもらうと気の重さが和らぐかもしれない、とも書いています[5]。

指示文の例（筆者の作例）

あなたは、取引先とのやり取りに慣れた営業の担当者です。
次のメモをもとに、取引先に送るメールの下書きを作ってください。
# 目的
打ち合わせの日を変えてもらうお願いと、おわび
# 材料
・〇日（火）の打ち合わせを、こちらの都合で延期したい
・候補は〇日（木）の午後か、〇日（金）の午前
・資料は前日までに送る
# 出力の形
件名と本文。本文は300字程度。ていねいに、ただし回りくどくしない

返ってきた下書きに「候補日を箇条書きに」「もう少し短く」などと足して直し、最後に日付や名前を自分で確かめます。ビジネスメールの基本の形は、ビジネスマナーの基本の記事にまとめています。

要約：短くする指示を重ねる

「さらに半分程度に」と重ねて、読みやすくする

事例集の要約の例では、「カタカナ語はやさしい日本語に」「わかりやすい箇条書きに」と指示したあと、「さらに半分程度に短く」などの指示を重ね、5回のやり取りで仕上げています。指示を繰り返して短くさせると、読みやすい要約になると説明しています[5]。

くわしく
  • 読み手を「小学生」とだけ書くと6年生向けになることがあり、学年まで決めるとよい[5]
  • メモ帳アプリとAIを組み合わせる使い方は、Obsidianと生成AIの記事で紹介している

会議：メモから議事録や報告を作る

メモにないことを足させず、事実と照らす

事例集では、会議中にとった箇条書きのメモを入れて報告用の資料を作らせ、事実と違うところがないか確かめてから使うよう呼びかけています[5]。総務省のガイドブックは、自治体の例として、文字起こしと生成AIで会議の議事概要を作る使い方を紹介しています[15]。

指示文の例（筆者の作例）

以下は、会議中にとったメモです。これをもとに、社内向けの議事録を作ってください。
# 出力の形
「決まったこと」「宿題（担当・期限）」「次回までに確かめること」の3つの見出しで、箇条書き
# ルール
・メモに書かれていないことは足さない
・担当や期限がメモから分からないものは「不明」と書く
# メモ
（ここにメモを貼る）

会議を録音したり文字起こししたりするときは、始める前に参加者に知らせましょう（筆者の提案）。Google も、Meet の「自動メモ生成」をオンにしたら、使っていることを全員に知らせるよう案内しています[16]。Teams や Meet に組み込まれた会議の要約の機能は、6章で紹介します。

校正：直した箇所も一緒に出させる

変更点の一覧があると、確かめやすい

事例集の校正の例は、文字起こしで作った議事録の誤字脱字を直す場面です。AIに「プロの編集者」という役割を与え、直した文と一緒に、どこを直したかを箇条書きで出させています。直した箇所を書かせると、変更箇所をチェックできると説明しています[5]。

東京都の事例集より（要点）

  • 役割：「あなたは、プロの編集者です」
  • 指示：誤字・脱字と、語尾の言い回しを直す
  • 追加：どこを直したかを箇条書きで書かせる
  • 材料：「#文章」の見出しの下に、直したい文を貼る

Excel：表の形を伝えて式を作らせる

どの列に何が入っているかを書くのがコツ

事例集の Excel の例では、A列に参加者名、B〜D列に条件を満たしたかどうか（1か0）が入っていると伝え、E列に入れる式を作らせています。回答の例は、3つの条件がすべて1なら「参加」と出す、IF と AND を組み合わせた式でした[5]。シートの構造を教えると、コピーしてそのまま貼れる関数が出てくると説明しています[5]。

指示文の例（筆者の作例）

# 指示
Excel で、条件に合う行を数える式を作ってください。
# 表の形
A列は日付、B列は担当者、C列は金額。データは2行目から100行目まで
# したいこと
担当者が「A」で、金額が10万円以上の件数を、F2セルに出したい
# 出力の形
式と、式の意味の説明を1行で

企画：案を出させ、次にリスクを聞く

案とリスクを、2回に分けて聞く

事例集では、立場（都の職員）と課題を書き、参考にする範囲や「項目ごとに期待される効果を説明してください」などの条件を付けて案を出させています。次の指示で、想定されるリスクを、種類を指定して案ごとに挙げさせています[5]。業務の課題の解決策を出させる例では、案の数（5つ）と、1つあたりの字数（100文字以内）を決めています[5]。

翻訳：日本語で確かめてから英語に

先に日本語の文案を作り、中身を確かめる

事例集の英文の招待状の例では、まず日本語で招待文を作らせ、次に「日本語の招待状案を英文にして下さい」と指示しています。できた英文をうのみにせず、内容をしっかり確かめてから送ることが必要としています[5]。英語の練習にAIを使う例は、オンライン英会話とAIの記事で紹介しています。

公開前の文を、別の目で読ませる

炎上のリスクを聞き、次に修正案を出させる

事例集では、SNSに載せる予定の文について、どの程度炎上のリスクがあるかと、その理由を聞いています。次の指示で、修正案と修正点を出させています。最初にリスクを洗い出し、次に修正を指示する、という段階的な聞き方です[5]。

指示文の書き方の型

東京都の手引きと、Microsoft・Google のプロンプトの書き方のページは、呼び方は違っても、似た要素を挙げています[2][3][17]。この記事では、共通する部分を「役割・目的と背景・材料・出力の形」の4つと、「やり取りで直す」にまとめました。

東京都の手引き：立場・目的と背景・出力形式

条件を整理してから、指示を重ねて直す

東京都の生成AI利用の手引き（2026年3月）は、Step1として「① 立場をはっきり」「② 目的・背景を具体的に指定」「③ 出力形式を指定」を、Step2として「④ プロンプトを重ねて回答をブラッシュアップ」を挙げています[2]。生成AIに「補助者」「案作成者」などの役割を与えると、業務に合った回答を得やすいとしています[2]。

くわしく
  • 「＃話し手」「＃分量」のように、＃の見出しで指示を整理する[5]
  • 出力の形は「200字以内」「箇条書き」「5項目」「ですます調」のように具体的に[5]
  • 論理的に考えさせる言葉として「ステップバイステップ」「段階的に」を挙げている[5]
  • 文部科学省の指針も、一度で求める答えを期待せず、対話を重ねて近づけるとしている[13]
Microsoft・Google・Anthropic の書き方のページの要点（各社の説明）
発行元書くこと書き方のコツ
Microsoft目的、コンテキスト（なぜ必要か、誰が関わるか）、ソース（使う情報）、期待する項目（どう答えてほしいか）の4つ[3]必要なのは明確な目標。ほとんどの場合、別の指示で結果をフォローアップする[3]
Googleペルソナ、タスク、背景情報、形式の4つ。例文に、どの部分がどれにあたるかの凡例を付けている[17]最初の回答を原案にして、内容を補い、指示を練り上げていく[17]
Anthropicしてほしいことを具体的に書き、出力の形と制約も書く。指示の理由（背景）も添える[18]職場の決まりや流れを知らない、優秀な新人に頼むつもりで書く。例は3〜5個[18]

使う前の決まりと、入れてよい情報

生成AIのサービスでは、入力したデータが保管・解析・学習などの処理に使われることがあります[4][7]。使い始める前に、会社の決まりと、入れてよい情報の範囲を確かめましょう。下の図は、資料の内容をもとに、目安を3段に分けたものです。

まず、会社の決まりと使ってよいツールを確かめる

会社が認めたツールを、決まりの範囲で使う

自治体での決め方の例として、東京都は、許可されていない生成AIを業務で使うことと、私物の端末で生成AIを使って業務をすることを禁止し、違反すると懲戒処分の対象になる場合があるとしています[2]。東京都は職員向けの環境として、令和6年4月から Microsoft Copilot を、令和7年3月から Microsoft 365 Copilot を使い始め、入力データが学習目的で保存されないことを確かめたとしています[2]。そのうえで、庁内の共通ツールに入力してよい情報の範囲を、情報の機密性の区分で決めています[2]。会社でも、認められた環境と、社内の情報の分類に従って使いましょう。国のAI事業者ガイドラインも、AIを使う事業者に、提供者が定めたサービス規約を守ることを求めています[6]。

くわしく
  • 組織の利用ガイドラインのひな形として、JDLAが「生成AIの利用ガイドライン」を公開している[19]
  • ひな形は、対象の生成AIや禁止する用途を、組織が書き込んで使う形になっている[4]
  • 総務省は2025年12月16日、自治体向けに職員の生成AI利用ガイドラインのひな形を加えた[20][15]
  • 社外に出したくない文書を自分のパソコンの中で扱う方法は、ローカルLLMの記事へ（使えるかは会社の決まりによる）

個人情報は、利用目的と学習の扱いを確かめる

本人の同意なく学習などに使われると、違反のおそれ

個人情報保護委員会は2023年6月2日の注意喚起で、事業者が個人情報を含む指示文を入れるときは、その個人情報の利用目的を達成するのに必要な範囲かを十分に確かめるよう求めました[7]。本人の同意なく個人データを入れ、それが応答を出す以外の目的で扱われると、個人情報保護法に違反するおそれがあるとして、提供者がそのデータを機械学習に使わないことなどを十分に確かめるよう求めています[7]。AI事業者ガイドラインも、個人情報を不適切に入力しないよう注意することを、AIを使う事業者に求めています[6]。

取引先の秘密や社外秘は、入れない

秘密保持契約の情報は、第三者への開示になりうる

JDLAのひな形は、取引先と秘密保持契約（NDA）を結んで受け取った秘密情報を外部の生成AIに入れると、提供者という第三者に開示することになり、NDAに反するおそれがあるとして、入力しないよう定めています[4]。自社の機密情報（ノウハウなど）も、法律上保護されなくなったり、特許出願ができなくなったりするおそれがあるとして、入力しないよう定めています[4]。IPAのガイドラインも、組織の内部文書や秘密保持契約を結んだ情報を、入力を制限するよう勧める情報に挙げています[14]。

くわしく
  • ひな形が挙げる入力の注意は6つ：他人の著作物、商標・意匠、著名人の写真や氏名、個人情報、NDAの秘密、自社の機密[4]
  • 個人情報も、入力が学習に使われるサービスでは入れない例文になっている[4]
  • サービスと条件によっては個人情報の入力が適法になりうるので、担当部門に確かめる形[4]

著作権：似せる使い方をせず、そのまま使わない

AIで作った物の利用も、ふつうの著作権と同じ基準

文化庁は、AIで作った画像などを公表したり販売したりするときは、通常の著作権侵害と同じ基準、つまり既存の作品との「類似性」と「依拠性」（既存の作品をもとにしたこと）で判断されると説明しています[21]。AIで作った物が著作物になるかどうかは、人に「創作意図」があるか、人が「創作的寄与」と認められる行為をしたかで判断されるとしています[21]。東京都の手引きは、AIで作った物はアイデアや構成案などの中間成果物として使い、最終的な成果物は職員が加筆・修正することで、著作物として守られる可能性を高められるとしています[2]。

くわしく
  • 文化庁の「AIと著作権に関する考え方について」は、令和6年3月15日の文書[22]
  • JDLAのひな形も、生成物はそのまま使わず、できるだけ加筆・修正するよう定めている[4]

人の評価に使うときは、本人への説明も

AIを使うことを、評価される人に知らせる

AI事業者ガイドラインは、AIの出力を特定の個人や集団の評価の参考にするときは、AIを使っていることを評価の対象の人たちに知らせるよう求めています。そのうえで、人による合理的な判断のもと、求めに応じて説明する責任を果たすこととしています[6]。

出力の確かめ方と、1件の仕事の流れ

ここまでの内容を、1件の仕事の流れにまとめると、次のようになります。

  1. ステップ1

    会社の決まりと、使ってよいツールを確かめる

    許可のないAIや私物の端末で業務をしない（東京都の例）[2]

  2. ステップ2

    入れる情報を選ぶ

    入れてはいけない情報（個人情報・取引先の秘密・社外秘など）を除く[4]

  3. ステップ3

    型に沿って指示する

    役割・目的と背景・材料・出力の形を書く[2]

  4. ステップ4

    やり取りで直す

    足りない条件を足して指示を重ねる[2]。2〜3往復が目安（筆者の提案）

  5. ステップ5

    事実・数字・出典を確かめる

    根拠や裏付けを、元の資料やほかのページで確かめる[2]

  6. ステップ6

    自分で仕上げる

    加筆・修正し、社外に出すなら「生成AIにより作成」などと書く[2]

根拠や裏付けを、必ず自分で確かめる

自然な文ほど、正しいと感じてしまいやすい

東京都の手引きは、生成AIの回答は表現が自然なため正しいと感じてしまうと注意したうえで、Copilot が示す参考のURLや資料についても、その中身が適切かは保証できないとしています。示された根拠をうのみにせず、ほかのサイトなどで事実を確かめ、必要に応じて複数の職員でチェックするよう求めています[2]。JDLAのひな形も、生成物を盲信せず、根拠や裏付けを自分で確かめるよう定めています[4]。

資料にないことは「ない」と答えさせる

答える範囲を、渡した資料の中に限る

東京都の手引きは、資料を登録したうえで「この資料の情報を基に」と聞き、「この資料に記載が無い場合はその旨回答してください。」と添える例を挙げています。資料にないことを聞いたときに、答えられないと返させることで、もっともらしいうそをつくリスク（ハルシネーション）を減らせるとしています[2]。

数字・日付・名前は、元の資料と照らす

合計や割合は、元の表で計算し直す

AIがまとめた文の中の数字・日付・人や会社の名前は、元の資料や表と1つずつ照らし、合計や割合は元の表で計算し直すのが確実です（筆者の提案）。IPAのガイドラインは、生成AIの出力には誤りが含まれることがあるので、常に正確さを確かめる必要があるとしています[14]。

社外に出すときは、AIで作ったことを書く

「生成AIにより作成」などと明記する

東京都の手引きは、内容を確かめたうえでAIの回答を対外的に使うときは、「生成AIにより作成」などと書くことで、AIによるものか人によるものかを読み手に伝えられるとしています[2]。IPAのガイドラインも、生成物を引用するときは、生成AIで作ったことを示すことが求められるとしています[14]。

最後は、自分で判断して仕上げる

AIの出力は参考の一つ。成果物の責任は人に

文部科学省の指針は教職員に向けて、AIの出力はあくまで参考の一つと認識し、自分でチェックして仕上げ、最後は自分で判断して成果物に責任を持つ、という姿勢が大切だとしています[13]。総務省の自治体向けのガイドブックは、用途によって求められる正確さが違うことを意識して、生成物を人が確認するルールを決めるよう示しています[15]。

Office・Google Workspace に組み込まれたAI

会社で Microsoft 365 や Google Workspace を使っていれば、その中にAIの機能が組み込まれていることがあります。ここでは、各社の説明から、仕事の場面でできることと、法人向けの料金をまとめます。どの機能が使えるかは、会社の契約や設定によって違います[23][16]。個人向けの Microsoft 365 などは、定番ソフトの記事で扱っています。

Microsoft：Copilot Chat は対象の法人契約で使える

追加料金なし。社内の資料は自分で渡して使う

Microsoft は、対象となる Microsoft 365 の法人向けの契約を持つ会社のアカウントなら、Copilot Chat を追加料金なしで使えると説明しています[24][25]。Copilot Chat (Basic) は主に Web の情報を使うAIチャットで、社内の資料を使うには、指示文に貼る、ファイルをアップロードする、Teams や Outlook で開いている内容に対して使う、などの形で自分で渡す必要があります[23]。

くわしく
  • 有料のアドオンがあると、会議・メール・チャット・ファイルなどの仕事のデータを使える[25]
  • アドオンなしでアプリ内の Copilot を使える区分は「Microsoft 365 Copilot (Basic)」[23]
  • (Basic) のアプリ内の機能として、Word の下書き・要約、Excel のデータ分析や数式づくりなどを挙げている[23]
  • 中小企業向けの Copilot Business は、Business プランを使う300ユーザー未満の会社が対象[26]

Teams 会議の要約や質問は、契約と設定しだい

組織の外で開かれた会議では使えない

Microsoft によると、Teams 会議の Copilot は、誰が何を言ったかなどの主な論点を要約し、やるべきこと（アクション アイテム）を提案し、会議中や会議後の質問に答えます[27]。会議が終わってから質問するには会議のトランスクリプト（文字起こし）が必要で、参加者の組織の外で開かれた会議では動きません[27]。Microsoft の区分の説明では、アドオンのない「Microsoft 365 Copilot (Basic)」のアプリ内の機能にも、Teams の会議の要約と文字起こしが挙がっています。ただし、使える機能はテナント（会社の契約の単位）の構成とライセンスによって違うとしており、アドオンなしで会議の要約が使えるかは、会社の契約と設定によります[23]。

くわしく
  • 会議後の「インテリジェント要約」は、Teams Premium か Copilot のライセンスで使える[27]
  • ライセンスなし（Copilot Chat のみ）では、仕事のデータを使えるのは「アップロードされたファイル」に限られる[25]
  • Microsoft が挙げる指示文の例：「議論したアイデアとその長所と短所を記載した表を作成します。」[27]

Google Workspace：Gemini をプランに組み込み

2025年1月の発表で、別料金のアドオンが不要に

Google は2025年1月16日、Gemini などのAI機能を Workspace の Business・Enterprise のプランに含め、アドオンを買わなくても使えるようにすると発表しました[28]。これに合わせて、プランの料金も改定しています[29]。Google Meet の「自動メモ生成」は、会議のメモを Google ドキュメントに自動で作って共有する機能で、日本語に対応しています。ただし一度に1つの言語にだけ対応し、複数の言語で話す会議には対応していません[16]。

くわしく
  • 自動メモ生成は15分から8時間までの会議向けで、対象のエディションかプランが必要[16]
  • 会議に遅れて入っても、「ここまでの要約」で話の内容をつかめる[16]

入力を学習に使わない、と各社は説明

法人向けの環境についての、各社の説明

Microsoft は、法人向けの Copilot と Copilot Chat のデータ保護の説明で、プロンプトや応答などのデータは基礎モデルのトレーニングには使用されないとしています[30]。Google も、Gemini アプリに送られたデータを人が確認することはなく、モデルのトレーニングに使われることもないと説明しています[29]。ただし、どの情報を入れてよいかは、これとは別に会社の決まりに従います（4章）。

オープンソースの便利なソフト：無料との違い、ライセンスの要点、用途別の代表例と安全な入れ方

  • 調査日: 2026年11月17日
  • 仕事・学習の道具

要点まとめ

  • オープンソースは「無料」とは別。ソース公開と改変・再配布の自由が条件[1][2]
  • 使うだけなら、会社でも義務はない。条件が付くのは外に配るとき[3][4]
  • 選ぶ軸は、公的なリスト・運営・ライセンス・対応OS・更新・公式の入手先
  • ドイツの州は、税務以外の職場の約8割を LibreOffice に移した[5]
  • 入手は公式サイトから。7-Zip の脆弱性は悪用も確認、更新が大事[6][7]

文書作成、写真の加工、動画の再生など、パソコンでよく使う作業には、オープンソースのソフトもあります。ただし「オープンソース」は「無料」と同じ意味ではありません。この記事では、オープンソースの意味と、使うだけの人に関係するライセンスの要点、選ぶときに確かめられる軸、用途ごとの代表的なソフト、行政での採用例、安全な入れ方を、公的機関と開発団体の公式情報でまとめました。特定のソフトを「一番よい」と勧めるのではなく、運営する団体・ライセンス・対応OS・最新版の日付・公的なリストへの掲載といった、確かめられる情報を並べています。メモアプリはObsidian の記事、パスワードの管理はパスワード管理の記事にまとめています。

オープンソースとは：「無料」とは別の話

ソースが見られるだけでは、オープンソースではない

配布の条件が、10の基準を満たす必要がある[1]

オープンソースの考え方を広めている団体 OSI（Open Source Initiative）の「オープンソースの定義」（1.9版、2007年3月22日最終改訂）は、ソースコード（プログラムの設計図にあたる文字の並び）が見られるだけでは足りず、配布の条件が10の基準を満たすことを求めています[1]。経済産業省の事例集（令和4年8月1日）も、OSS（オープンソースソフトウェア）を、ソースコードが公開され、利用・改変・再配布が誰に対しても許可されているソフトと説明し、同じ10の条件を紹介しています[2]。

くわしく
  • 自由な再配布、ソースコードの利用の自由、派生物の利用の自由を認める[2]
  • 特定の人や集団、使う分野で差別しない[2]
  • たとえば、仕事（ビジネス）で使うことを制限してはならない[1]
  • 特定の製品に限らない、ほかのソフトを制限しない、特定の技術に縛らない[2]
  • この定義は、Debian（Linux の配布版の一つ）の指針がもとになっている[1]

無料でも、オープンソースとは限らない

無料で配られる、中身を公開しないソフトもある[2]

経済産業省は、OSS と対比されるものとして、改変や複製が制限された「プロプライエタリソフトウェア」を挙げています。ソースコードを公開しなかったり、使用許諾契約で使い方を制限したりするもので、多くは有償の商用ソフトですが、無償で提供されるもの（フリーソフトウェア）もあると説明しています[2]。逆に、自由ソフトウェア（オープンソースに近い考え方）を広める GNU プロジェクトは、そのコピーをお金を払って手に入れた人もいるだろうと書いています[8]。

くわしく
  • 英語の「free」には「無料」と「自由」の意味があり、まぎらわしい
  • GNU は、自由ソフトウェアは値段ではなく自由の問題だとしている[8]
  • GNU は「無料」という言い回しは避けるのが最上だとしている[8]
  • GNU が挙げる「第零の自由」は、どんな目的でも望むままに実行する自由[8]

項目オープンソースプロプライエタリ

利点と、気をつけたい点

透明性などの利点の一方、サポートの期間に注意[2]

経済産業省の事例集は、OSS を使う利点として、開発費の抑制と開発期間の短縮、高い安定性・品質・透明性、ベンダロックイン（特定の会社の製品から乗り換えにくくなること）の回避を挙げています[2]。気をつける点としては、ライセンスを守ること、サポート期間が比較的短くサポートが十分でない場合があること、取引先などサプライチェーンでの使われ方を挙げています[2]。企業向けの資料ですが、サポート期間と更新は、個人で使うときにも確かめたい点です（筆者の見解）。

使うだけなら何に気をつける？ ライセンスの要点

オープンソースのソフトには、それぞれライセンス（利用の条件）が付いています。主なライセンスの説明を読むと、条件が付くのは「使う」ときではなく、主に「外に配る」ときです。

使うだけなら、義務はない

個人でも会社でも、使うこと自体に条件はない[3]

Mozilla の MPL（Mozilla Public License）の FAQ は、MPL のソフトを使うためにしなければならないことは「Nothing（何もない）」で、個人でも会社でも誰でもどんな目的にも使え、義務が生じるのは組織の外に配布したいときだけだと説明しています[3]。GPL（GNU General Public License）第3版も、改変していないプログラムを実行する許可は無制限だと明記しています[9]。

くわしく
  • VideoLAN は、VLC などの使い方に制限はなく、仕事や行政などどんな目的にも使えるとしている[10]
  • 7-Zip は、会社のパソコンを含め、どのパソコンでも使えると明記している[11]

社内で改変して使うだけなら、公開しなくてよい

組織の中で作るコピーは「配布」に当たらない[4]

GNU の FAQ は、GPL のプログラムを改変し、公開せずに個人的に使うのは自由で、組織（企業を含む）でも同じだとしています[4]。組織の中で複数のコピーを作って使うのは配布ではなく、コピーをほかの組織や個人に渡したときに配布になると説明しています[4]。MPL の FAQ も、会社や組織の中での改変や配布は「private（私的なもの）」に当たり、義務はないとしています[3]。

外に配るときは、ライセンスの条件を守る

ソースの共有、表示を残すなど、種類で条件が違う

ライセンスは、外に配るときの条件の厳しさで、大きく3つに分けて説明されることがあります。経済産業省の事例集に載った国内企業の例では、条件の厳しい順に、コピーレフト型（GPL、AGPL など）、準コピーレフト型（EPL、MPL など）、非コピーレフト型（Apache、MIT、BSD など）としています[2]。

外に配るときの主な条件と、この記事で取り上げるソフトの例
型外に配るときの主な条件例
コピーレフト型（GPL など）ソフトを公に配るときは、改変した部分も共有する（Blender の説明）[12]GIMP・Inkscape・Blender・VLC・OBS Studio など
準コピーレフト型（MPL など）「ファイル単位」のコピーレフト。他のライセンスのコードとも組み合わせやすい[3]LibreOffice・Firefox・Thunderbird
非コピーレフト型（Apache・MIT など）ライセンス文や著作権表示を付ける・残す[13][14]VSCodium（MIT）[15]
くわしく
  • MIT は、使用・複製・改変・販売などを無料で許し、条件は著作権表示と許諾表示を残すこと[14]
  • Apache 2.0 は、再配布の条件を第4条にまとめ、受け取る人にライセンスの写しを渡すことなどを求める[13]
  • Blender は、配るときに改変も共有させるこの性質を「コピーレフト」と呼ぶと説明している[12]

作った作品は、作った人のもの

Inkscape や Blender は、作品は作者のものと明記

Inkscape は、Inkscape で保存・書き出したファイル（svg、png、pdf など）は、作品を作った人のものだとしています[16]。Blender も、Blender で作った画像や動画、.blend ファイルは作った人だけのもので、自由に使えると説明しています[12]。

くわしく
  • Noto Sans CJK と源ノ角ゴシックは、SIL Open Font License 1.1 で配られている[17][18]
  • IPAex フォントの「IPAフォントライセンス」は、2009年4月1日に OSI から定義に準拠すると認定された[19]
  • IPAフォントは、印刷物やデジタル・コンテンツで文字として使える[20]

補足

この章は、ソフトを使う人向けの要点です。ソフトを改変して配る、製品やサービスに組み込むといった場合は、そのソフトのライセンスの全文を確かめる必要があります（筆者の見解）。

選ぶときに確かめる軸と、用途別の代表例

オープンソースのソフトは、誰が作り、どの条件で、いつまで更新されているかを、公式の情報で確かめられます。筆者が考える、選ぶときに確かめたい6つの軸を表にしました。

選ぶときに確かめる6つの軸
軸どこで確かめるか例
① 公的機関のリストフランス政府の SILL など下の表のソフトは、いずれも SILL に載っている[21]
② 運営する団体公式サイトの「About」「Legal」などVLC の VideoLAN は、プロジェクトであり非営利団体[10]
③ ライセンス公式サイトの「License」や、配布物の COPYING同じソースから作られても、配布版のライセンスが違うことがある（下のカード）

⑤ 更新の頻度リリースノートや更新履歴7-Zip は2026年に、26.00（2月）から26.06（11月）まで版を重ねた[23]
⑥ 公式の入手先公式サイトのアドレス総務省は、公式サイト等の信頼できるサイトからの入手を勧める[6]

フランス政府の「SILL」は、公的機関向けの推奨リスト

2026年11月17日時点で672件のソフトが載っている[21]

SILL（Socle interministériel de logiciels libres、省庁横断のフリーソフトの基盤）は、フランスの公的機関向けに推奨されるフリーソフトのリストです。ソフトごとの担当（リファレント）を自ら引き受けた公務員がまとめ、フランス政府のデジタル部局（DINUM）が code.gouv.fr で公開しています[24]。国の保証は付きませんが、誰でも自由に無料で使えるとしています[24]。2026年11月17日に公開データを数えると、672件が載っていました[21]。

くわしく
  • SILL のデータは、フランス政府のデータサイト data.gouv.fr でも毎週更新されている[24]
  • SILL はフランスの公的機関向けのリストで、日本の制度とは関係がない（筆者の注意）
  • 7-Zip のライセンスは、SILL と開発元の記載が食い違う。開発元を優先したい[21][11]

名前が似ていても、配布版のライセンスが違うことがある

VS Code の配布版は、Microsoft 製品のライセンス[47]

Microsoft によると、プログラムを書くためのエディタ Visual Studio Code は、ソースのリポジトリ「Code - OSS」に Microsoft 独自の変更を加え、従来の Microsoft 製品のライセンスで配っているものです[47]。リポジトリ自体は MIT ライセンスです[47]。配布版のライセンスは「MICROSOFT SOFTWARE LICENSE TERMS」です[48]。一方、VSCodium は、Code - OSS から作ったバイナリ（すぐ使える形のプログラム）を MIT ライセンスで配り、テレメトリ（利用状況の送信）を無効にしていると説明しています[15]。

パスワード管理は、ライセンスと対応OSだけ確かめる

使い方や選び方は、パスワード管理の記事で

パスワード管理ソフトでは、KeePassXC が GPLv3 で配られ、macOS 12 以降・Windows・Linux 向けの版があります[45]。Bitwarden のクライアントは、GPL v3.0 と Bitwarden License v1.0 の二本立てです[49]。管理ツールの使い方や、紙のメモとの使い分けは、パスワード管理の基本にまとめています。

ドイツの州：税務以外の職場の約8割が LibreOffice に

Office と Outlook は、削除済みか作業中[5]

ドイツのシュレースヴィヒ＝ホルシュタイン州は、2024年4月の発表で、LibreOffice を標準のオフィスソフトとして全面的に導入する閣議決定を示し、州行政の職員約3万人の IT 職場をオープンソースへ移す方針を打ち出しました[51]。計画には、Windows から Linux への移行なども含まれます[51]。2025年12月の州の発表では、税務の部門以外の職場の「ほぼ80%」で LibreOffice が使われ、Microsoft Office と Outlook はアンインストール済みか作業中としています[5]。

くわしく
  • 州は、ライセンス費をすでに1,500万ユーロ超節約していると説明している[5]
  • 一方、2026年に移行と開発のための一時的な投資900万ユーロを見込む[5]
  • メールは、約4万4千のメールボックスを Open-Xchange に移した[5]
  • 残る約20%の職場は、業務システムの都合で Word や Excel が必要[5]
  • 州は、業務システムの多くが今は Windows 用で、Linux では動かないと説明している[54]

デンマーク：デジタル化省が2025年6月に試験を開始

一部の職員が、Office の代わりに Collabora を試す[52]

デンマークのデジタル化省は、一部の職員が、案件処理システム「F2」の中で Microsoft Office の代わりに、LibreOffice をもとにした Collabora を試す試験を始めました。省本部での試験の開始は2025年6月19日です[52]。大臣は、これですぐに大手 IT 企業を追い出せるとは思っていないとし、正しい方向への一歩と位置づけています[52]。

会津若松市：2012年から LibreOffice を庁内標準に

導入当時の試算は、約5年で約1500万円の削減[50]

福島県会津若松市は、2008年10月からの事務用パソコン240台の入れ替えで、原則としてオープンオフィス（OpenOffice.org）だけを入れ、2012年4月から LibreOffice を庁内標準のオフィスソフトとして全面的に採用しました[50]。2007年の導入当時の試算では、有償ソフトを15%程度併用しても、パソコンが入れ替わる約5年間で約1500万円程度の削減効果があるとしています。市は、この試算は現在の状況とは異なると注記しています[50]。

くわしく
  • 市のページの記載は、2014年7月に全パソコンへ LibreOffice 4.0.6.2 を入れたところまで[55]

デジタル庁：「源内」の一部を OSS として公開

重複開発を防ぎ、特定の事業者への依存を抑える[53]

デジタル庁は2026年4月24日、政府職員が使う生成AIの基盤「源内」の一部を、商用利用できるライセンスで、無償の OSS として公開しました。公開したのは、Web 画面の部分のソースコードと構築手順などです[53]。自治体や政府機関で似た AI 基盤を重複して開発するのを防ぎ、特定の事業者やサービスへの依存を抑えながら運用できることを狙いに挙げています[53]。

見方: SILL の公開データで、ソフトごとに利用者か担当者（リファレント）がいると登録した組織を、筆者が数えました[21]。職員の自己申告にもとづく数なので、実際に使っている機関や人の数を表すものではありません。Krita は2026年5月29日、KeePassXC は2025年11月21日に載ったばかりです[21]。

安全な入れ方：公式サイトから入れ、更新を続ける

口コミのリンクから、偽のダウンロードサイトへ

総務省は、公式サイト等からの入手を勧めている[6]

総務省は、検索の上位に出た口コミサイトのリンクから、有名なダウンロードサイトに似せた偽のホームページに誘導され、画像加工ソフトに見せかけたマルウェア（悪意のあるソフト）を入れてしまった事例を紹介しています。新種だったため、入れたときにはマルウェア対策ソフトも検知できませんでした[6]。予防法として、公式サイト等の信頼できるサイトから入手したソフトを使うよう勧めています[6]。

くわしく
  • IPA は、サービス名で検索すると、検索結果の最上位に罠の広告が出ることがあると注意している[56]
  • IPA の注意はサポート詐欺についてだが、検索結果の広告に気をつける点は同じ（筆者の見解）

公式サイトでも、一緒に入るものを確かめる

Audacity は「MuseHub なし」の入手も用意している[35]

Audacity の公式サイトには、「Download Audacity」のほかに、「Download without MuseHub」（MuseHub なしでダウンロード）というボタンがあります[35]。MuseHub は、同じサイトでプラグインやアプリなどを販売するサービスとして案内されています[35]。ダウンロードの画面に選択肢があれば、何が一緒に入るのかを読んでから選ぶと安心です（筆者の提案）。

更新を続ける：7-Zip の脆弱性は悪用も確認

米国の当局が、悪用された脆弱性の一覧に加えた[7]

7-Zip の脆弱性 CVE-2025-0411 は、細工した圧縮ファイルを展開すると、ネットから来たことを示す印（Mark-of-the-Web）が展開したファイルに引き継がれず、その印による保護を回避されるおそれがあるものです[7]。米国の脆弱性データベース NVD の記録では、米国の CISA（サイバーセキュリティ・インフラストラクチャー安全保障庁）が2025年2月6日に「悪用が確認された脆弱性」の一覧に加えています[7]。対象は24.09より前の版で、深刻度（CVSS v3.1）は10点満点の7.0です[7]。

くわしく
  • 7-Zip は2024年11月29日の24.09で、入れ子の書庫で印が伝わらない不具合を直した[23]
  • 2026年も、26.01〜26.06 で脆弱性の修正が続いている[23]
  • 26.03 では、印を保てない別の脆弱性（CVE-2026-58052）を修正した[23]
  • 経産省は、脆弱性情報の入手先として、IPA と JPCERT/CC の JVN を紹介している[2]

更新の通知が出たら、速やかに更新する

サポートが切れたソフトは、脆弱性が直らない[57]

総務省は、更新の通知が表示されたら速やかに更新し、自動更新の機能があれば有効にするのもよい方法だとしています[57]。サポート期間が切れたソフトは、脆弱性が見つかっても修正されないと注意しています[57]。たとえば LibreOffice の26.2系は2026年11月30日でサポートが終わり、その後は不具合やセキュリティの修正が出ないため、開発団体は26.8.3への更新を勧めています[25]。

ソースが公開されていても、混入は起きる

XZ Utils に、共同開発者が悪意あるコードを入れた[58]

2024年3月29日（現地時間）、Linux などで使われる圧縮ツール XZ Utils に、悪意のあるコードが入れられていたことが分かりました。JPCERT/CC によると、共同開発者が2024年2月24日ごろに入れたもので、対象は5.6.0と5.6.1です。特定の条件では、SSH（遠隔操作の仕組み）を通じて外部から接続されるおそれがありました[58]。NVD の深刻度は10点満点の10.0です[59]。ソースが公開されていることは、安全の保証そのものではありません（筆者の見解）。

くわしく
  • NVD は、配布用の圧縮ファイル（tarball）に悪意のあるコードが見つかったとしている[59]
  • JPCERT/CC は、版の確認は xz コマンドでなく、パッケージ管理ソフトで行うよう勧めた[58]
入れる前・入れた後のチェックリスト（総務省・IPA などの説明をもとに筆者がまとめたもの）
確かめること理由
□ 公式サイトのアドレスを確かめ、ブックマークから開く総務省は、公式サイト等の信頼できるサイトからの入手を勧める[6]
□ 検索結果の広告や、口コミサイトのリンクから入らない罠の広告が検索結果の最上位に出ることがある[56]。偽サイトへの誘導の事例もある[6]
□ 対応OSと、サポート中の版かを確かめるサポートが切れたソフトは、脆弱性が修正されない[57]
□ 一緒に入るものの選択肢を読む公式サイトでも、付属サービスの有無を選べることがある[35]
□ 更新の通知が出たら更新する。自動更新があれば有効に総務省が勧めている[57]

EU のサイバーレジリエンス法：オープンソースには特別な扱い

収益化していないオープンソースの提供は、商業活動とみなさない[68]

EU のサイバーレジリエンス法（CRA）は、ソフトやハードなどデジタル要素のある製品を買う消費者と企業を守るための法律で、2024年12月10日に発効しました[69]。主な義務は2027年12月11日から、報告の義務は2026年9月11日から適用されます[69]。収益化していないオープンソースの提供は商業活動とみなさず、自分の責任でないプロジェクトにコードを寄せる開発者にも適用しません[68]。

くわしく
  • 新しい区分「オープンソース・ソフトウェア・スチュワード」は、商業向けのOSSを継続して支える法人[68]
  • スチュワードはセキュリティ方針などの義務を負うが、行政上の罰金の対象外[68]
  • スチュワードの報告義務は、2027年12月11日から[64]
  • 欧州委員会は、2026年7月27日に実務の手引きを公表した[69]
  • 義務の対象は製造者などで、使うだけの人に新しい義務を課す法律ではないと考えられる（筆者の見解）
